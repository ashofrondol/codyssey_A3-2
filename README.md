## 프로젝트 개요

동영상은 시간 순서로 이어진 이미지(프레임)의 묶음이다. 앞뒤 프레임의 차이를 보면 무엇이 움직이고 어디로 가는지 알 수 있다. 이 미션에서는 OpenCV로 영상 속 움직이는 객체를 감지하고, 객체마다 고유 ID를 붙여 따라가는 추적 시스템을 직접 만든다. **배경 차분**(움직이지 않는 배경을 빼서 움직이는 부분만 남기는 방법)으로 움직임을 찾고, **특징점 매칭**(물체의 모서리·무늬 같은 눈에 띄는 점을 비교하는 방법)으로 미리 등록한 물체를 다시 알아본다. 두 사람이 겹쳐 지나갈 때 ID가 뒤바뀌거나 조명이 바뀔 때 추적이 무너지는 현상을 숫자로 측정해, "위치 정보만으로는 객체를 구분할 수 없다"는 한계와 외형을 학습하는 딥러닝 접근이 왜 필요한지 스스로 이해하는 것이 목표다. 이 역량은 Mobility(보행자/차량 추적), Smart Factory(라인 모니터링), Robotics(작업자/부품 추적), Healthcare(재활 동작 모니터링), E-Commerce(매장 동선/물류 추적) 등에서 쓰인다.

**핵심 과제** (명세의 "최종 결과물")

1. 웹캠 또는 비디오 파일을 프레임 단위로 분석하고, 바운딩 박스·궤적·ID·FPS를 화면에 표시하며 키보드로 제어하는 애플리케이션을 만든다.
2. 움직이는 물체를 배경과 분리해 감지하고, 고유 ID를 유지하며 추적하고 이동 경로를 선으로 그린다.
3. 미리 등록한 물체가 영상에 나타나면 특징점 매칭으로 찾아 표시한다.
4. 추적 성능을 정량적으로 측정하고, 고전적 컴퓨터 비전의 한계와 딥러닝이 필요한 이유를 분석 보고서로 정리한다.

## 개발 환경과 제약 사항

**개발 환경**

- Python 3.8 이상
- 권장 환경: Python 3.10+, OpenCV 4.5+
- SIFT 사용 시 `opencv-contrib-python` 필요, ORB는 기본 `opencv-python`으로 가능

**금지 사항**

- YOLO, SSD, R-CNN 등 딥러닝 객체 탐지 모델 사용 금지
- OpenCV의 `dnn` 모듈 사용 금지
- MediaPipe 등 고수준 AI 라이브러리 사용 금지

**구조 및 산출물 조건**

- `Tracker` 클래스는 별도 파일(`tracker.py`)로 분리하여 구현한다.
- 정량적 성능 측정 결과가 보고서에 포함되어야 한다.
- ID Switch 횟수와 조건별 실패율을 반드시 측정한다.

**데이터셋 조건** (테스트 영상 가이드)

- 평가용 표준 시나리오로 최소 1개 영상을 사용한다.
- 필수: "두 객체 겹침" 시나리오 (20~30초)
- 권장: "조명 급변", "정지/재등장" 시나리오 각 1개
- 웹캠 직접 촬영 또는 공개 데이터셋(PETS, MOT Challenge 등) 활용 가능하다.

## 할 일

명세의 기능 요구 사항이다. 끝낸 항목은 `[x]`로 바꾼다.

### 1. 영상 입출력 및 제어

영상을 한 프레임씩 읽어 오고, 초당 처리 프레임 수(FPS)를 보여 주며, 키로 프로그램을 제어한다.

- [ ] `cv2.VideoCapture`를 사용하여 웹캠 또는 비디오 파일을 읽는다.
- [ ] 현재 FPS를 계산하여 화면에 표시한다.
- [ ] 키보드 이벤트를 처리한다: `q` 종료, `s` 현재 프레임 저장, `p` 일시정지

### 2. 배경 차분 (Background Subtraction)

배경 모습을 기억해 두고 현재 프레임과 비교해 달라진 부분(전경)만 남긴다. 모폴로지 연산은 흰 영역을 깎거나 불려서 잡티를 지우고 구멍을 메우는 처리다. 학습률(learning rate)은 배경 모델이 새 프레임을 얼마나 빨리 받아들이는지 정하는 값이다.

- [ ] `createBackgroundSubtractorMOG2`를 사용하거나, `absdiff`로 직접 차영상을 구현한다.
- [ ] 모폴로지 연산(열림, 닫힘)을 적용하여 노이즈를 제거하고 객체를 덩어리로 만든다.
- [ ] 배경 모델의 학습률(learning rate)을 최소 3가지 값으로 조절하여 효과를 관찰한다.

### 3. 객체 감지

전경 덩어리마다 테두리를 찾고, 물체를 감싸는 사각형(바운딩 박스)과 가운데 점(중심점)을 구한다.

- [ ] 움직임이 감지된 영역에서 윤곽선을 추출한다.
- [ ] 면적 필터링을 통해 너무 작은 움직임은 무시한다.
- [ ] 각 객체의 바운딩 박스와 중심점을 계산한다.

### 4. 객체 추적 (Tracker 클래스 구현)

이전 프레임과 현재 프레임에서 서로 가장 가까운 물체를 같은 물체로 보고 같은 ID를 이어 붙인다.

- [ ] `Tracker` 클래스를 별도 파일(`tracker.py`)로 구현하여 ID 관리 로직을 분리한다.
- [ ] 이전 프레임의 객체들과 현재 프레임의 객체들 간 거리를 계산한다.
- [ ] 가장 가까운 객체끼리 같은 ID로 매칭한다.
- [ ] 일정 프레임 이상 등장하지 않는 객체는 ID를 삭제한다.
- [ ] 새로 등장한 객체에는 새 ID를 부여한다.
- [ ] 각 객체의 이동 경로를 저장하고 화면에 선으로 표시한다.

### 5. 특징점 매칭

등록한 물체 사진의 특징점과 매 프레임의 특징점을 비교해, 그 물체가 화면에 있는지 판단한다. ORB와 SIFT는 특징점을 찾고 설명하는 대표적인 방법이다.

- [ ] 추적하고 싶은 물체의 이미지 1장을 미리 로드한다.
- [ ] ORB 또는 SIFT를 사용하여 특징점을 추출한다.
- [ ] 매 프레임에서 해당 물체의 특징점을 매칭한다.
- [ ] 매칭 성공 시 화면에 "TARGET DETECTED" 메시지를 표시한다.

### 6. 정량적 성능 측정

테스트 영상을 보면서 추적이 틀린 횟수를 직접 세어 기록한다.

- [ ] ID Switch 횟수(객체의 ID가 잘못 바뀐 횟수)를 수동으로 측정한다.
- [ ] 추적 실패 횟수(객체가 화면에 있는데 감지되지 않은 횟수)를 수동으로 측정한다.
- [ ] 조건별(겹침, 정지, 조명 변화) 실패율을 기록한다.
- [ ] 측정 프로토콜: 각 조건별 20~30초 영상에서 표의 테스트 횟수만큼 이벤트를 관찰/기록한다.
- [ ] 기록 템플릿: "영상명 - 조건 - 프레임 범위 - ID Switch 수 - 실패 수 - 관찰 메모" 컬럼으로 정리한다.

## 보너스 과제

### 보너스 1. Hungarian Algorithm 구현

Hungarian Algorithm은 여러 이전 객체와 여러 현재 객체를 짝지을 때 전체 거리 합이 가장 작아지는 짝을 찾는 방법이다. Greedy 매칭은 가장 가까운 짝부터 하나씩 정하는 방법이다.

- [ ] 거리 행렬을 기반으로 최적 할당 문제를 푸는 Hungarian Algorithm을 직접 구현한다.
- [ ] scipy 없이 NumPy만으로 구현한다.
- [ ] Greedy 매칭 대비 성능 차이를 비교한다.

### 보너스 2. 침입 감지 구역 설정

- [ ] 화면 내 특정 영역(사각형)을 마우스로 지정한다.
- [ ] 해당 영역에 객체의 중심점이 들어오면 경고 메시지를 출력한다.
- [ ] 침입 발생 시 로그를 저장한다.

### 보너스 3. IoU 기반 매칭

IoU는 두 사각형이 겹친 넓이를 두 사각형을 합친 넓이로 나눈 값(0~1)이다.

- [ ] 중심점 거리 대신 바운딩 박스의 IoU(Intersection over Union)로 매칭한다.
- [ ] 두 방식의 성능 차이를 ID Switch 횟수와 추적 유지율로 비교한다.

### 보너스 4. 칼만 필터 기반 예측

칼만 필터는 지금까지의 움직임으로 다음 위치를 예측하고, 실제 관측값으로 그 예측을 보정하는 방법이다.

- [ ] `Tracker`에서 `cv2.KalmanFilter`를 활용하여 객체의 다음 위치를 예측한다.
- [ ] 예측값을 매칭에 활용한다.
- [ ] 칼만 필터 적용 전/후 ID Switch 비율을 비교한다.

- **실행 화면 예시**: 왼쪽 위에 `FPS: 28.4`, 객체마다 초록색 박스와 `ID:1`, `ID:2` 라벨, 빨간색 궤적선, 등록된 물체 발견 시 `[TARGET DETECTED]` 표시, 아래에 `Press 'q' to quit, 's' to save snapshot` 안내가 있는 화면. 그림은 명세 PDF의 결과 예시 참고.

- **추적 실패 케이스**:

```
상황: 두 사람이 화면 중앙에서 겹쳐 지나감

원인: 위치 정보만으로는 두 사람을 구분할 수 없음
시도: 거리 임계값 조정 → 근본적 해결 불가
```

## 명세에서 확인할 점

- **표시 문구가 두 가지**: 최종 결과물 3번은 등록된 물체가 등장하면 "Target Found"를 표시한다고 하고, 기능 요구 사항 5와 결과 예시는 "TARGET DETECTED"를 표시한다고 한다. 이 README는 기능 요구 사항의 "TARGET DETECTED"를 따랐다.
- **보고서 요구 사항이 확정인지**: 보고서 절 제목이 "보고서 요구 사항(확인 필요)"로 되어 있어, 이 요구 사항이 최종본인지 명세상 분명하지 않다.
- **필수 영상과 측정 조건의 범위가 다름**: 테스트 영상 가이드는 "최소 1개 영상"과 "두 객체 겹침" 시나리오만 필수이고 "조명 급변", "정지/재등장"은 "권장"이다. 그러나 보고서 표는 "객체 일시 정지" 5회, "조명 변화" 5회 측정을 요구하고, 제약 사항은 "ID Switch 횟수와 조건별 실패율을 반드시 측정한다", 측정 프로토콜은 "각 조건별 20~30초 영상"이라고 한다. 권장 영상 없이 이 조건들을 어떻게 측정할지 명세에 나와 있지 않다.
- **매칭률 계산식**: 특징점 매칭 성능 표의 "매칭률"을 어떻게 계산하는지(예: 매칭된 특징점 수 ÷ 추출된 특징점 수), 그리고 "추출된 특징점 수"가 등록 이미지 기준인지 프레임 기준인지 명세가 정의하지 않았다. 매칭 "성공"으로 판단하는 기준도 정해져 있지 않다.
- **결과물 파일 이름과 보고서 형식**: `tracker.py` 외의 애플리케이션 파일 이름과 보고서 형식(Markdown, PDF, 노트북 등)을 명세가 정하지 않았다.
